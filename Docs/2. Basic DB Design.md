## Notation

- `PK`: Primary key
- `FK`: Foreign key
- `PK,FK`: Column is part of a composite primary key and is also a foreign key
- `unique (...)`: Uniqueness constraint
- `nullable`: Column may contain `NULL`
- Types and enumerated values are shown as provided in the source schema.

```text

USERS
```

## Module 8: Content (Elasticsearch-Backed)

```text

CONTENT_ITEMS
  PK  content_id            uuid
  FK  tenant_id             uuid       -> TENANTS
      content_type          string     (news, blog)
      title                 string
      body                  text
  FK  author_id             uuid       -> USERS
      status                string     (draft, pending_approval, published,
                                         rejected, archived)
  FK  approved_by           uuid       -> USERS (nullable)
      approved_at           timestamp  (nullable)
      published_at          timestamp  (nullable)
      created_at            timestamp
      updated_at            timestamp

CONTENT_VERSIONS
  PK  version_id            uuid
  FK  content_id            uuid       -> CONTENT_ITEMS
      version_number        int
      title_snapshot        string
      body_snapshot         text
  FK  edited_by             uuid       -> USERS
      edited_at             timestamp

CONTENT_ATTACHMENTS
  PK  attachment_id         uuid
  FK  tenant_id             uuid       -> TENANTS

      file_url              string
      file_type             string

SEARCH_SYNC_LOG
  PK  sync_id               uuid

      error_message         string     (nullable)

CONTENT_OUTBOX_MESSAGES
  PK  message_id            uuid       (same shape as IAM_OUTBOX_MESSAGES)

```

### Elasticsearch Index

The following index is not a PostgreSQL table; it is owned by the Content module.

```text
content_index: content_id, tenant_id, content_type, title, body,
```

## Implementation Notes

- The `TENANTS` table is the tenant-level parent entity. Tenant-scoped records carry a `tenant_id` foreign key where shown.
- Each functional module has an outbox message table. The source schema indicates that these tables share the same structure as `IAM_OUTBOX_MESSAGES` unless otherwise specified.
- The Content module's Elasticsearch index is separate from the PostgreSQL tables.
